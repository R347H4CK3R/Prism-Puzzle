# Durable Prism suggestion queue

Chris asked to finish the remaining Prism implementations. The existing app has an authorized no-secret manual-copy suggestion handoff, and the existing Dot review is enabled daily at 09:00 America/Chicago from November 13. Do not add a schedule, in-app agent, credential or network dependency.

Use a small offline queue adapter around the reviewed suggestion contract. An authenticated caller fetches the complete issue/comment snapshot, verifies consistent metadata and current owner policy, then supplies data to this tool. Issue content remains untrusted and is hashed in memory, never persisted as prose or used as commands or policy. Exact metadata schemas and bounded arrays fail closed. Checkpoints live only in the private repository, updated with an expected-head lease; failed or uncertain writes are checked before retry. The tool itself reads stdin and writes stdout, never choosing files, reaching the network, sending messages or mutating GitHub.

Preserve original creation plus 30 elapsed days, all assessments, closed/missing records and delivery receipts. Changed content or comment revisions require fresh substantive review. New issue text cannot supply assessments. Missing previously tracked issues are reported rather than erased or marked complete. Only open unfinished records receive deadline alerts: seven days, one day, then overdue. Keep only the most urgent current threshold; acknowledge a notice only after verified user delivery. Deduplicate by issue, revision and threshold so a failure to deliver is retried and meaningful edits may produce a new notice. Released/declined records do not nag. Capacity exhaustion blocks rather than truncates.

Alternatives considered: keyword auto-classification cannot assess feasibility safely; credential-bearing in-app submission expands privacy/access scope; a GitHub issue-triggered executor lets untrusted text reach execution. Keep the existing accountable daily Dot evaluator and add deterministic private bookkeeping instead. No IPA rebuild/version change is warranted for developer-only tooling; the verified 1.1.3 build 6 catalog remains current.
